CORE PRODUCT PRINCIPLES

The following principles are non-negotiable.

1. Deterministic mathematics

Mathematical answers must be generated and verified through deterministic code. A language model must not be treated as the final mathematical authority.

2. Reproducibility

Every generated question must have a seed. The same generator version, configuration, and seed must reproduce the same:

- Question
- Parameters
- Diagram
- Answer
- Distractors
- Solution
- Metadata

3. Separation of concerns

Keep these components separate:

- Curriculum structure
- Generator logic
- Mathematical solver
- Validator
- Renderer
- Question-bank storage
- User interface
- Export system

4. Independent verification

Where practical, the method used to verify an answer must be independent from the method used to generate it.

5. Original generation

Do not create questions by merely replacing numbers in copied source questions. Extract the underlying mathematical structure and create original generator specifications.

6. Modular development

Do not create one enormous source HTML file containing the entire system.

Build a modular source project that can produce polished standalone HTML applications as deployment outputs.

7. Offline capability

Core generation, validation, question-bank use, editing, and exporting must be able to operate without an internet connection.

8. Security

Never place private API keys, database credentials, or secrets inside a downloadable HTML file.

9. Traceability

Every item must be traceable to:

- Curriculum objective
- Generator
- Generator version
- Seed
- Difficulty profile
- Review state
- Creation date
- Modification date
- Relevant source evidence

10. Accessibility

Accessibility must be built into the architecture, not added as an afterthought.

GENERATION STRATEGIES

Use the mathematical strategy appropriate to each domain.

Examples include:

- Arithmetic: constrained exact-number generation
- Fractions: reduced rational arithmetic
- Algebra: construct backwards from a selected solution
- Simultaneous equations: choose the intended solution before forming equations
- Geometry: construct valid coordinates and relationships before drawing
- Trigonometry: control angles, sides, exact values, and rounding
- Probability: construct complete valid sample spaces or distributions
- Statistics: generate seeded datasets with intended properties
- Combinatorics: enumerate small cases and verify formulas
- Graph theory: create valid graph structures before asking questions
- Decision mathematics: run the relevant algorithm to verify the result
- Calculus: construct functions from intended derivatives or antiderivatives
- Differential equations: select valid solution families before forming questions
- Linear algebra: construct matrices from intended rank, determinant, eigenvalues, or solution structure
- Modelling: generate context, variables, assumptions, units, data, model, and interpretation rubric together
- AI mathematics: generate controlled data, matrices, vectors, probability models, objective functions, and optimization tasks

VALIDATION REQUIREMENTS

General checks must include:

- Reproducibility
- Mathematical correctness
- Defined domain
- Valid parameter ranges
- Nonzero denominators
- Valid dimensions
- Valid units
- Valid rounding instructions
- Unique correct response
- No duplicate distractors

- No accidental answer leakage
- No malformed notation
- No invalid HTML
- No inaccessible visual-only information

Domain-specific validation must include appropriate checks.

Examples:

- Substitute algebraic answers into the original equation.
- Differentiate proposed antiderivatives.
- Verify matrix equations directly.
- Enumerate small probability sample spaces.
- Recalculate statistics from the raw data.
- Verify geometry from coordinates and constraints.
- Run shortest-path, spanning-tree, flow, scheduling, or network algorithms.
- Confirm graph properties.
- Confirm dimensions and units in modelling problems.

Use exact arithmetic whenever possible. Floating-point comparisons must use explicit tolerances.
