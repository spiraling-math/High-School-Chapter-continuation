# SPI-Math Question Bank Platform — Development Roadmap

> Status: living document. Scheduling is owner-controlled; this roadmap expresses **sequence, dependencies, and exit criteria by phase and milestone**, not calendar dates. Where a fact is not yet settled it is marked **Unknown / to be decided**.

---

## 1. Vision and Guardrails

### What "done" looks like at maturity
A reproducible, offline-capable system that produces validated mathematics assessment items across levels (preschool → first-year university, with university **reserved**), where:

- Every item is generated by a **deterministic generator** keyed by an explicit curriculum **objective ID** and a **seed**.
- Every item's correctness is established by an **independent verification oracle**, not by an LLM and not by the generator's own arithmetic.
- A complete authoring-to-export pipeline exists across the product family: **Generator Studio**, **Question Bank Manager**, **Assessment Builder**, **Quality Console**, and (later) **Student Preview**.
- Output artifacts (worksheets, answer keys, worked solutions, standalone HTML) are **self-contained, offline, and secret-free**, and are **traceable** back to objective ID, generator version, and seed.

### Non-negotiable principles (constrain every phase)
| Principle | Meaning in practice |
|---|---|
| Deterministic mathematics | Math truth comes from code + the verification oracle. No LLM is a math authority. |
| Reproducibility via seeds | `(generator, version, seed)` reproduces an identical item, bit-for-bit. |
| Separation of concerns | Generation, solving, validation, rendering, storage, and export are distinct layers. |
| Independent verification | A second, independent implementation (the oracle) confirms each item's answer. |
| Original generation | AI capstones are DRAFT/REFERENCE only; bank items are regenerated and re-validated. |
| Modular development | One domain, one generator, one objective at a time; vertical slices before breadth. |
| Offline capability | Core generation, validation, and export run with no network. |
| Security | No secrets, keys, or credentials in HTML or shipped artifacts. |
| Traceability | Every item records objective ID, generator + version, seed, and validation status. |
| Accessibility | Accessible structure, math markup, and contrast are built in, not retrofitted. |

## 3. Phase 1 — Foundation & First Vertical Slice *(current)*

**Objective:** prove the entire pipeline, end to end, on a single generator — **IBDP AA SL, Chapter 1: Sequences and Series → Arithmetic Sequences** — so the pattern can be replicated.

### Pipeline to prove (ordered)
1. **Objective** — pin the curriculum objective ID for arithmetic sequences.
2. **Generator** — deterministic generator: `(objectiveId, seed) → item parameters`.
3. **Seeded generation** — identical output for identical seed; bounded, sane parameter ranges.
4. **Exact solution** — closed-form, exact (rational/symbolic where needed), no float drift.
5. **Distractors** — derived from a **misconception model** (e.g., off-by-one on term index, confusing `d` with `aₙ`), not random noise.
6. **Validation** — the independent **Python oracle** recomputes the answer and confirms it; mismatches fail the item.
7. **Rendering** — accessible math markup; deterministic, secret-free output.
8. **Bank storage** — item persisted with full traceability metadata.
9. **Preview** — render and inspect a generated item.
10. **Edit** — adjust/curate while preserving determinism and validation.
11. **Export** — single-item export path that later generalizes to full artifacts.
12. **Automated tests** — unit + property + golden-set tests.

### Milestones (ordered, with dependencies)
| # | Milestone | Depends on | Notes |
|---|---|---|---|
| 1.1 | Author core **schemas** (Item, Objective, Generator metadata, Validation record) | — | Schema-first; drives every layer |
| 1.2 | Write **architecture docs** (layer boundaries, data flow, traceability fields) | 1.1 | Records separation-of-concerns contract |
| 1.3 | Stand up **Python oracle** (reference implementation) | 1.1 | Runs now; no JS runtime required |
| 1.4 | Implement **arithmetic-sequences generator** (Python first) | 1.1, 1.3 | Deterministic, seeded |
| 1.5 | Build **distractor / misconception** logic | 1.4 | Seeds the misconception library |
| 1.6 | **10,000-seed validation** harness vs. oracle | 1.3, 1.4 | Core gate |
| 1.7 | Capture a **golden set** (frozen seeds + expected outputs) | 1.6 | Regression anchor |
| 1.8 | **Install Node.js runtime** *(explicit milestone)* | — | Enables TypeScript production layer + Vitest |
| 1.9 | Port/implement generator in **TypeScript**; reconcile against oracle & golden set | 1.7, 1.8 | TS = production layer |
| 1.10 | **Vitest** automated tests (unit, property, golden) | 1.8, 1.9 | CI-ready |
| 1.11 | Minimal **render → store → preview → edit → export** path | 1.9 | Thin but complete |

> **Runtime decision (explicit):** Python hosts the **oracle and reference implementation now**; **Node.js must be installed** to build the TypeScript/browser production layer and run Vitest. The oracle remains the independent check even after the TS layer exists — the two implementations must agree.

### Exit criteria (Phase 1)
- One **production-quality** arithmetic-sequences generator.
- Passes **10,000-seed** validation against the independent oracle with **zero** mismatches.
- A committed **golden set** guards against regression.
- The full slice (objective → … → export) runs offline and is reproducible from seeds.

## 4. Phase 2 — Broaden Sequences/Series & Harden the Core

**Objective:** replicate the proven pattern within the same domain and stand up the first two apps.

### Workstreams
- **More generators, same domain:** geometric sequences, arithmetic/geometric series (finite sums), sigma notation, applications/word problems, and recurrence-style items — each following the Phase 1 per-generator DoD.
- **Question Bank Manager MVP:** store, search, filter, and **version** items by objective ID, generator, seed, difficulty, and validation status.
- **Quality Console MVP:** surface validation results, golden-set status, distractor coverage, and flag items needing review.

### Exit criteria
- ≥3 in-domain generators each meeting the per-generator DoD (incl. 10,000-seed validation).
- Bank Manager can persist, retrieve, search, and version validated items with full traceability.
- Quality Console renders pass/fail validation status and review flags for every banked item.

## 5. Phase 3 — Generator Studio MVP & Assessment Builder MVP

**Objective:** make authoring and assembly productive, and produce real deliverable artifacts.

### Generator Studio MVP
- Configure objective + parameters, generate seeded previews, inspect distractors/misconceptions, and curate items into the bank.
- Edits preserve determinism and re-trigger validation.

### Assessment Builder MVP
- Assemble an assessment from banked, validated items (by objective ID, difficulty, count).
- Reproducible assembly (assessment recorded as a set of `(generator, seed)` references).

### Export artifacts (all offline, secret-free)
| Artifact | Contents |
|---|---|
| Worksheet | Questions only, accessible layout |
| Answer key | Final answers keyed to items |
| Worked solutions | Step-by-step exact solutions |
| Standalone offline HTML | Self-contained, no external/network dependencies, no secrets |

### Exit criteria
- An author assembles an assessment from the bank and exports **all four** artifact types, fully offline.
- Exported HTML is self-contained and contains no secrets.

## 8. Risk-Based Sequencing & Dependencies

- **Schemas precede everything.** Item/Objective/Validation schemas (1.1) gate all downstream layers.
- **Oracle precedes generators.** Independent verification (1.3) must exist before a generator is trusted (1.4+).
- **Vertical slice precedes breadth.** Phase 1 must fully close before Phase 2 broadens the domain.
- **Node.js install gates the production layer.** No TypeScript/browser layer or Vitest until 1.8 is done; Python carries Phase 1 verification in the interim.
- **Bank Manager precedes Assessment Builder.** You cannot assemble from a bank that cannot store/version validated items.
- **Generators precede exports.** Worksheets/keys/solutions require validated banked items.
- **Foundational domains precede dependent ones.** Number/algebra/functions before calculus; per the domain ordering above.
- **Strong-coverage levels precede thin ones.** AA SL first; university deferred until curriculum docs arrive.

## 9. Definition of Done

### Per generator
- Bound to an explicit **objective ID**.
- **Deterministic** and **seed-reproducible**.
- Produces an **exact** solution (no float drift).
- Distractors derive from a documented **misconception model**.
- Passes **10,000-seed** validation against the independent oracle with zero mismatches.
- Has a committed **golden set** and passing automated tests.
- Renders accessibly; output is offline and secret-free.
- Full **traceability** metadata recorded (objective ID, generator + version, seed, validation status).

### Per app
- Implements its slice of the pipeline within the agreed **layer boundaries** (separation of concerns).
- Operates **offline** for its core function.
- Emits **no secrets** in any artifact it produces.
- Preserves **determinism and validation** across any edit/assembly it performs.
- Surfaces **traceability** to the user where relevant.
- Meets baseline **accessibility** requirements.
- Covered by automated tests appropriate to its layer.
